## ⛔ 4. THREE FORMAT TRAPS IN ONE SOURCE, EACH OF WHICH PRODUCED A WRONG NUMBER FIRST

All three are in `edgar_abs_ee_cmbs`, and all three are the project's existing rules re-earning
themselves:

1. **Dates are `MM-DD-YYYY` STRINGS.** `SAFE_CAST(maturitydate AS DATE)` returns NULL on every row,
   so the first measurement reported **0 loans maturing within 24 months** and **0 anchor leases
   expiring**. Parsed properly: **95 and 109**. An ISO parse on a non-ISO date does not error.
2. **Occupancy is a FRACTION and `0` is the null sentinel.** `0.8534` means 85.34%. Counting
   `<= 60` on the raw value reported **705 properties at or below 60% occupancy**; almost all were
   unpublished zeros. Corrected: **39 of the 603 that publish a figure.** *Unpublished is NULL,
   never 0.*
3. **`paymentstatusloancode` is a CREFC code, not a number.** `0` is *current*; `A` and `B` are
   grace-period and under-30-days. Reading "non-zero means late" would admit 20 rows that are fine.

## ⛔ 5. G145 — THE PLAN'S OWN DIAGNOSIS WAS WRONG, AND THE DEFECT WAS 36% OF THE SET

The next-session prompt named the cause as `MAX(IF(si_admitted, last_past_event_date, NULL))`
dropping a date when a second signal is undated. **`MAX()` ignores NULLs, so that cannot produce the
symptom.** Acting on it would have shipped a change that looked like it worked.

⭐ **The real cause is one line up:** `last_past_event_date = MAX(IF(a.obs <= CURRENT_DATE(), a.obs,
NULL))` — **an event in the FUTURE contributes no date at all.**

**Measured: 8,573 of 23,819 flagged parcels printed *date unknown* over a date we hold.** The
dominant case is a scheduled tax auction. Parcel `471401230011000005` goes to auction on
**2026-09-28** and the screener said we did not know when.

⭐ Fixed with `si_next_event_date` (**MIN**, not MAX — for something that has not happened, the
soonest date is the one you act on), `si_events_future`, and `si_signal_dates`, an array carrying
**every date for every signal** with its basis, source and keying. A fourth render state —
**scheduled/upcoming**, badged as the strongest label rather than the weakest — qualifies
unconditionally and is checked BEFORE the cutoff and recency tests, because both count past events
only and would have excluded it for having none.

**After: 8,591 rescued, 945 genuinely undated**, and those 945 now read *"the publisher does not
date this record"*, never *"date unknown"*.

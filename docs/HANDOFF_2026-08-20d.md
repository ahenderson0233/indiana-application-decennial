## ⭐ 2. THE SIX FINDINGS THAT CHANGE WHAT YOU BELIEVE

### ① The address is STATEWIDE. Three documents said Marion-only, and all three were wrong.

G125, the previous handoff and the backlog all recorded *"address is Marion-only and must say
so"*. That rests on `in_si_address_parcel_bridge` — 51,309 Marion rows — which is the address

`energy.parcels_in` is a different source doing the reverse lookup, and it carries the DLGF's own

the candidate set: **527,038 of 531,325**.

carry a coordinate, **0 carry neither**.

### ② Adding 379,165 roads made the right-of-way test WORSE, and that is the whole G122 story.

The old test was *"does a held road cross this polygon"*. It was only ever safe because we held
1,086 roads. With the full TIGER All Roads corpus, measured over three counties, `ST_INTERSECTS`
fires on **7,052 of 23,678 parcels that are NOT ribbon-shaped**, against **55** before.

**A test whose positives rise 128× because the corpus grew is measuring the corpus.**

The replacement asks whether the road runs ALONG the parcel:
`along_ratio = road centreline length inside / (perimeter / 2)`.

⛔ **Indiana publishes no right-of-way class code** — Marion's own class descriptions contain no
ROAD / RIGHT / STREET / HIGHWAY / ALLEY row. So the class code cannot identify a road; it
**exonerates** one. Road-crossing rate by band: 6xx public **23.3%**, unclassed 10.0%, 8xx 6.9%,
1xx agricultural **1.7%**, 5xx residential **1.1%**. It saved **1,317** long thin farm fields and
house lots from exclusion.

## ⛔ 4. SEVEN INSTRUMENT FAILURES, AND ONE OF THEM CORRUPTED SEVEN PAGES

**This is the most useful section in the file. In every case the instrument was wrong before the
code was.**

1. ⛔ **A join on the wrong key.** `in_parcel_assembly.parcel_key` is the STATE parcel number;
   `parcels_in.parcel_id` is the county's dashed form. Joining them reported *"99.0% of candidates
   carry no class code"* against a column measured **97.8% populated**. Every figure from that
   probe was void. The key is `state_parcel_id`, and 38,840 of them repeat, so the parcel side
   must be de-duplicated and the fan-out asserted.
2. ⛔ **Looking for the data in the wrong table.** The queue-id buses are in
   `in_bus_capacity_tier0`, not `in_pjm_bus_locations_v2`, which holds only PSS/E labels and never
   had a queue id in it. The first probe returned 0 and looked like a refutation.
3. ⛔ **`re.split` WITH A TWO-GROUP REGEX WROTE GARBAGE INTO EIGHT PAGES.** `re.split` returns
   EVERY capture group, so `(<(script|style)\b...)` interleaved the bare word "script" between the
   chunks and the loop appended it as content: `</script>scriptscript`. ⚠ **The markup stayed
   well-formed, so no audit could see it** — it was caught by reading the page in a browser.
4. ⛔ **A regex cannot parse this codebase's rendered text.** A template literal nested inside the
   `${...}` of another template is the shape almost every rendered string here uses, and a regex
   closes the outer template on the inner backtick. The spelling fixer missed six real
   occurrences and **the matching audit then reported ZERO and looked like a clean bill of
   health.** Both now use `scripts/js_prose.py`, a real lexer with the nested case as its first
   self-test, proven on an 11-case injected regression.
5. ⛔ **An audit registered but not dispatched runs and reports nothing.** Both new checkpoint
   audits matched their pattern, stored their result and fell off the end of the `if/elif` chain
   in silence. The checkpoint printed eight audits while ten had run. There is now an `else` that
   fails loudly.
6. ⛔ **Two audits that count different populations will disagree forever.** After G122 the
   payload held 23,766 flagged parcels and the warehouse query said 23,795, and the honesty audit
   shouted that one of them was lying to a user. Neither was — the exclusion has to be applied on
   **both** sides.
7. ⚠ **Crying wolf, then a silent zero, in the same instrument.** The ledger's read-before-write
   detector reported **57** (counting the ordinary "measure what we just produced" read), then
   **0** (a report filter still matching an older wording while the detector was correctly

1. ⛔ **NEVER WRITE A REGEX THROUGH A SHELL HEREDOC. SEVENTH OCCURRENCE, and it was mine.** `\n`
   inside a character class arrived as a literal newline and left an unterminated string. Later
   the same session, a heredoc edit silently applied *half* of a two-part change — widening a
   lookup table but not the regex that feeds it — leaving a check that passes by default.

   `export_sites_exact.py` and the checkpoint caught it. An export is on the path to what the user
   sees, so the app could no longer be rebuilt without the platform session's dataset. The clip is
   now `in_parcel_location`, a build we own.
3. ⛔ **A PRESENTATION POLICY MUST NOT DEPEND ON THE TAB BEING VISIBLE.** The dense policy first
   used `requestAnimationFrame` and applied **nothing**, because rAF does not fire in a tab that
   is not compositing. This project already knows that hazard from the other end —
   `boot_map_harness.js` exists to patch rAF so the map boots headless.
4. ⛔ **AN `id` IS USUALLY ON THE BLOCK, NOT INSIDE IT.** The relocation guard searched a block's
   INNER html for live ids, found one in 1 block of 63, and broke six pages (18 fatal findings).
   The pages are written `<div class="sowhat" id="wd-answer">measuring…</div>`.
5. ⛔ **A LOOKALIKE IS SOMETIMES A KEY.** `fits_mw_datacentre_at_4_per_acre` is a **CSV column
   name** the user's spreadsheets depend on; `circle-color` and 91 siblings are MapLibre paint
   properties. The spelling pass is token-wise and skips anything containing an underscore.
6. ⚠ **APPLY EDITS TO ONE STRING IN ONE REVERSE-ORDERED PASS.** Splits and deletions were applied

   from the wrong place.
7. ⚠ **A HARD RELOAD IS NOT OPTIONAL.** A stale cached page served `common.js?v=b6a36660` while

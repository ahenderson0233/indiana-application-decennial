## ⭐ 2. WHAT THE LADDER HAS ACTUALLY PROVEN — and it is not what was expected

The ladder was run to answer one question: **does a larger request surface FACILITIES that a small
request never binds?** Because 146 of the vendor's 298 binding facilities are absent from our
harvest, and if the ladder surfaced them, PJM parity would follow.

**Measured on completed rungs:**

| comparison | new constraint keys | new facilities |
|---|---:|---:|
| withdrawal 5,000 vs 100 MW | **0** of 410,947 | **0** of 1,029 |
| injection 5,000 vs 10 MW | **443** | **0** of 1,300 |

⭐ **So the answer is a qualified no, and the qualification matters.** A bigger injection request
IS a strict superset — 443 new (bus × facility × contingency) keys appear at 5,000 MW that never
appear at 10 MW, and none go the other way. But **not one new FACILITY appears in either
direction.** The monitored set is a property of the STUDY CASE, not of the request size.

⛔ **Therefore the ladder cannot close the 146-binder gap**, because that gap is facilities. PJM
parity needs a different attack. Keep running the ladder if the per-rung *fit* comparison is
wanted — that is a real product question — but do not expect parity from it.

⚠ **The directions behave differently and must not be pooled.** Withdrawal added nothing; injection
added 443. That is consistent with the documented direction asymmetry (their injection binds like
our strictest rule, their withdrawal like our most permissive).

⚠ Both tables carry ~102,000 duplicate rows (655,790 rows over 553,719 distinct keys). The figure
is near-identical across rungs, so it is structural to the harvest and NOT a repair artefact — but
**always dedupe on (bus, facility, contingency) before comparing anything.**

## 3. THE REPAIR, AND THE TECHNIQUE WORTH KEEPING

`in_pjm_qs_c23_inj_5000` held **1,801 of 1,826 buses** while carrying all 74 markers, so the runner
believed it complete and would never have returned. Exactly 25 buses — one whole batch — marked
done with rows that never landed, because that harvest was killed mid-batch.

⭐ **How the missing batch was identified without any log.** Every row the loader writes in one
batch shares a single `_pulled_at`, stamped once per batch. So in a COMPLETE table for the same
case and owner, grouping by `_pulled_at` and ordering by it reconstructs the batches in the order
the loader walked them — and the bus ORDER is a property of the (case, owner) option list, not of
the requested MW. That pinned it to **batch index 30** exactly, so one marker was archived instead
of re-running all 74.

something the reader legitimately skips.

batch-30 gap in §3 — the cure caused the disease.

## 12. THE STANDING RULES

**Write boundary.** `energy-platfrom.energy` is **READ-ONLY**; everything goes to
`energy-platfrom.indiana_app`. The one permitted write is an APPEND to `energy.registry_sources`.
**Restate this in every agent brief — agents do not inherit it.**

**Every table gets a `_registry` row in the same run**, with `source`, `method` and a verbatim
`RE-SCRAPE COMMAND:`.

**⛔ Check the warehouse before you explore or scrape.** It has paid for itself seven times.

**Read the schema. Never guess a column name or type.** `bus_number` is STRING; `rows` and
**`nulls`** are reserved; `state_boundaries` has `geom`; `in_substations` has `substation_type`.

**⚠ Never write a regex through a shell heredoc** — use the Write tool.

**Unpublished is NULL, never 0.** ⚠ But a STATED zero is not an absent value — I&M prints
`0.000 $/kW` on Tariff G.S. and that is correct (G57).

**⚠ EXCLUDE `parcels_in/080500000047000018`** from every spatial join — D85, whole-Earth polygon.

**⛔ No centroid where a footprint exists.** **Never `git add -A`**; use a commit-message FILE.

**After ANY front-end change:** `stamp_assets.py` → `audit_frontend.py` → verify in a browser →
check the deployed site. ⚠ `app.js` is boot-critical and **the map does not boot headless** —
verify by calling functions directly (`renderLayerLegend()`, `openDossier()`).

⚠ **`data/sites/` is ~224 MB of already-gzipped files and pushes FAIL on it**
(`SEC_E_MESSAGE_ALTERED`). If a push dies after a sites re-export, that is why.
